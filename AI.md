# AI Use

The only AI tool I used during this challenge was ChatGPT. I mainly used it as a tutor and mentor rather than as a way of generating the finished solution for me. Early on, I established that I wanted to think through problems myself first, with ChatGPT pointing me towards the relevant concept or next step rather than immediately providing the answer. I found this incredibly useful because some of the terminology and Python concepts were familiar to me, but I had not necessarily used them in exactly the same way before.

A large part of the value came from being able to question why something worked rather than only being told what to write. For example, I spent time understanding how YAML data is represented in Python, why a `set` was useful for checking duplicate ports, how relative paths should be resolved, how environment variables are checked, and why exit codes become useful once automation is involved. I also used ChatGPT to help break the project into smaller stages, which made it much easier for me to focus on one problem at a time without unnecessarily expanding the scope.

I believe AI suggestions are becoming increasingly accurate, but even with a relatively small command-line project like this one, not every suggestion was correct or complete on the first attempt. One example was the initial pre-commit configuration using `language: system` which ChatGPT suggested. When I tested the hook through my normal Git workflow, it failed because `pytest` was not available to Git in that environment. I used the error message to understand what had happened, changed the hook to use its own managed Python environment, and then tested it again before committing.

Another example, although not necessarily an AI failure, was the automation itself. When I initially suggested the project, ChatGPT focused mainly on the technical checks and did not really consider the wider development workflow. It was only later, when I started thinking about how easy it would be to forget manual checks such as running the test suite before committing changes, that I decided some form of automation would make sense. This eventually led to the pre-commit hook. A future improvement would be to make ComposeCheck itself easy to use as a pre-commit check in another project.

I also feel it is important to point out that I did not rely on AI suggestions without checking them. During the challenge I regularly looked at external examples and explanations, particularly W3Schools, GeeksforGeeks, Stack Overflow and Reddit, to confirm syntax and understand concepts in more detail or through clearer examples. On top of that, I tested changes manually throughout the project, deliberately changed values to compare different outcomes, and later added pytest tests covering both successful and unsuccessful cases. The pre-commit hook then gave me another way of checking that the test suite continued to pass before a commit was accepted.

Finally, I also used ChatGPT to help with the written documentation. The experiences, decisions and reflections are my own, but I dictated much of the context and my thoughts and used ChatGPT to help organise them into clearer Markdown. I then reviewed the drafts myself, changed parts which did not reflect what I meant, and asked for the wording to remain as close as possible to the way I normally write.
